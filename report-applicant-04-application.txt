6. FAILURE NARRATIVE - WHAT ACTUALLY FAILED
------------------------------------------------------------------------------
GET /cpc-types/ is the only endpoint that worked: 135 of 135 returned 200 (p95
226 ms). It returned an empty list, so the database has no CPC types.

Two reference endpoints fail on missing schema regardless of login: GET
/requirement-types/ returned 500 (relation "core_requirementtype_cpc_types"
does not exist) and GET /proprietorship-types/ returned 500 (relation
"core_proprietorshiptype" does not exist). GET /routes/ returned 404 ("Unknown
CPC type") because there is no CPC type id to pass.

The setup login failed (500), so all ten authenticated endpoints answered 401:
draft create, list, document upload, finalize, my applications, resubmit, both
petition endpoints and both operator-sheet endpoints. The per-application
reads and the draft document DELETE were skipped because no draft or
application id was available.

8. HYPOTHESIS UNDER TEST (from the test brief)
------------------------------------------------------------------------------
  Operating System Out-Of-Memory (OOM kills) forcing backend workers down due
  to intensive real-time server-side PDF document layout compilation entirely
  inside RAM.

Status: NOT OBSERVED and NOT EXERCISED. Contradicted by the code.

Evidence from the backend source:
- Contradicted: the applicant-side generators return Word documents built with
  python-docx (build_petition_docx, build_operator_sheet_docx;
  applications/views.py:1182 and :1276), with the DOCX content type. No PDF is
  compiled on these routes. The only PDF conversion in the backend is docx2pdf
  in legal/document_generation.py, on the staff side.

- Contradicted: no worker died. The listening process kept PID 6780 for the
  whole suite and its working set did not grow.

- Not exercised: both document endpoints answered 401, so their memory
  behaviour under concurrency remains untested.

- Spec corrections: petition-document and operator-sheet-document accept POST
  only (the brief lists GET), so the script uses POST. /routes/ requires
  ?cpc_type=<id>.

- Separate defect found by reading the code: resubmit_application
  (applications/views.py:989) checks neither ownership nor current status and
  sets any application to pending_receiving. Any logged-in user can rewind any
  application by id. The script targets id 0 by default so it cannot alter
  real data.
